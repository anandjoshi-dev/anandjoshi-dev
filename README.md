I build and lead teams on systems that stay correct and fast under real load — high-throughput services, event-driven pipelines, latency-sensitive request paths, and the observability that keeps them honest.

I'm domain-agnostic by design, and by track record. I've shipped in **finance and media platforms**, **ad tech**, **desktop-as-a-service infrastructure**, and **tracking, experimentation, and data platforms**. Four problem spaces with almost nothing in common at the surface — and underneath, the same questions every time. Consistency, failure modes, coupling, latency budgets, the cost of a bad abstraction. The vocabulary changes; that's the fastest part to learn.

> Most of my work lives behind a corporate firewall, so this profile is about **how I think** rather than a wall of repo links.

---

### 🧭 How I work

**Design in the open** — non-trivial changes start as a diagram and a trade-off doc. If I can't draw it, I don't understand it yet.
**Learn a domain by modeling it** — find the invariants, find where the state actually moves, draw it, pressure-test it with the people who've lived it.
**Reliability is a feature, not a phase** — failure modes and rollback come out of the same conversation as the happy path.
**Optimize second-order effects** — the best change makes the next ten cheaper.
**Leadership is leverage, not distance** — still reading the diffs, still writing the tools.
